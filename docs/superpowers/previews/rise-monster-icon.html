怪物图标 · 放到怪物名称前面

Rise Overlay · 纯 XAML 实现 · 数据来自真实 WPF 离屏渲染（RenderTargetBitmap，非 HTML 模拟）

本页数据已全部作废重做。上一版的推荐属性、部位名、徽章文案都是手写的假夹具， 导致「怪异克服天廻龙 = 4 推荐」这类错误结论。现在工装直接吃真实静态库 RiseOverlay.Data/static/monsters-overlay.json + 真实 MonsterHudMapper， 不手写任何一条数据。修正清单见第七节。

一、做法：不碰逻辑，只加一层声明式映射

HUD 数据里本来没有怪物 ID（MonsterHudDto 只有 string Name）。但顺着数据链追下去，Name 的来源是确定的：

monsters-overlay.json
   id    : "monster_089_05"
   title : "嗟怨震天怨虎龙"      ←── 逐字就是 HUD 上的 Name
        │
        ├─ MonsterStaticStore.FindByTitle(monster.Name) ─→ dto
        └─ MonsterHudMapper.BuildFromStatic(dto).Name = dto.Title

图标文件：em089_05_icon.png      id 换个前缀就是文件名，79/79 只大型怪零缺失

所以不需要往 DTO 里塞 ID、不需要转换器、不需要 code-behind——用 Name 当键，纯 DataTrigger 查表就够了。112 个非空标题零重名，键是唯一的。

图标和名字永远在同一行——图标列 Width="Auto"、名字列 Width="*"，两个列定义并排，物理上不可能换行。 命中不到图标（英文名 / 未收录怪）时 Image 整体 Collapsed，宽度回退到加图标前的水平。

二、实测：真实数据下的全场景

工装流程：MonsterStaticStore.Load() → FindById() → MonsterHudMapper.BuildFromStatic() → 合成战斗帧 → MergeLive()。推荐属性与部位全部由静态库派生。全部 越界 0。

回应质疑：怪异克服天廻龙到底几个推荐

推荐属性只有「龙」一个。静态库聚合后 fire 25 / water 0 / ice 5 / thunder 15 / dragon 30， ElementRecommend.FromHitzones 只取等于最大值的属性 → 只剩 dragon。此前写「4 推荐」是编的。

最坏情况：怪异克服天彗龙（7 字名 + 4 推荐）

名字被砍成「怪异克服…」——7 个字只剩 4 个。这是全库唯一会截断的情形（共 2 只，见第三节）。

标题行对照：每一刀各管多少

左列数字为「名字可用宽度 / 完整所需宽度」。b4（胶囊整列让位）是唯一大幅富余的方案； b2（图标缩到 16px）与 b3（徽章压到 1 字）都不足以救回。

常见情况与回退

左：静态库未命中（英文名 Apex Rathalos）→ 图标收起、0×0、不留空位，名字拿回全部宽度。 右：任务简报面板复用同一个字典，字号 14、行更高，20px 图标在这里更好认 —— 但同样的 2 只天彗龙在简报里也被截断（名字需要 98px = 7×14px，只分到 77px，缺 21px）。 根因相同，修法也相同。

嗟怨震天怨虎龙（7 字名 + 2 推荐，唯一可捕的长名怪）

推荐 Water+Thunder（聚合后两属性并列最大），部位 12 个。名字 130.1px 可用，完整显示。

七、此前那版数据错在哪 诚实记录

上一版工装用手写夹具造 DTO，三处编造：

项我写的（错）真实（静态库）
怪异克服天廻龙 推荐属性fire + water + ice + thunder（4 个）dragon（1 个）
嗟怨震天怨虎龙 推荐属性fire（1 个）water + thunder（2 个）
嗟怨震天怨虎龙 部位头部 / 前肢 / 腹部 / 尾巴 / 背鳍（7 个）12 个（头部 / 躯干 / 右臂 / 左臂 / 背部 / 尾巴 / 后脚 …）
最坏情况样本怪异克服天廻龙（推荐数错了）怪异克服天彗龙 / 神秘红光天彗龙
最坏情况徽章文案「当前任务可捕」（该怪根本不进这个分支）「不可捕」（capturable=false）

第 5 条最阴：预算实验里 SetText(v, "可捕", "当前任务可捕") 在真实画面上找不到目标文本，静默失败， 于是「改前 / 改后」两张图完全一样，却被当成有效对照读出了结论。

另一个独立 bug：判据用了 TextBlock.DesiredSize.Width 当「文本完整宽度」。 它会被父级列宽夹紧，同一个 7 字名在有图标时报 63.8px、无图标时报 90px——自相矛盾。 已换成 FormattedText 独立测量（不受布局约束），现在稳定报 84px。

教训：凡是要拿数据下结论的工装，夹具必须来自真实数据源。手写夹具不是「简化」，是把结论建在沙子上。

八、怎么调

图标大小只有一个数，在 Resources/MonsterIcons.xaml：

<!-- HUD 里图标的渲染边长；想放大就改这一个数 -->
<sys:Double x:Key="Hud.MonsterIconSize">20</sys:Double>

重做图标资源（换了原画目录、或静态库增删了怪）：

python Scripts/gen_monster_icons.py          # 重出 PNG + XAML，并清理孤儿文件
python Scripts/gen_monster_icons.py --xaml   # 只重出 XAML
